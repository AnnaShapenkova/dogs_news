# T14 — результаты и оставшаяся приёмка

Код утверждённой T14 реализован локально. Реальный выпуск в Mini App/Telegram не подтверждён: агент не вызывал модель, не подключался к рабочей БД и не развёртывал Coolify.

## Запуски

Python 3.12.10, существующий psycopg: `python -m unittest discover -s tests -p 'test_*.py' -q` — 118 тестов, 75 пройдены, 43 PostgreSQL-теста пропущены (TEST_DATABASE_URL не задан). `node tests/test_mini_app.js` — два сценария пройдены. Перед добавлением новых сценариев существующий набор также проходил; проверки с реальной БД не выполнялись.

## Критерии SPEC

| Критерий | Результат |
| --- | --- |
| Пределы этапов и строгий JSON | Проверены draft=6000, review=2400; модель, temperature и отсутствие новой reasoning-настройки сохранены. Даже валидный JSON с finish_reason=length не принимается. |
| Безопасная диагностика 402 | Проверены известные limit_source/payment_reason, числовой Retry-After и отсечение неизвестных значений, oversized/невалидного тела и секретов. Ответ ошибки читается до 32 KiB; полный текст не сохраняется. |
| Остановка после первого 402 | Unit-проверки вызова сохранения паузы на отдельном audit connection и отсутствия новых резерваций/пустых прогонов пройдены. Реальные PostgreSQL-проверки draft/review, следующего collected и нового соединения написаны, но пропущены. |
| Сохранение паузы после сбоя/новых суток | PostgreSQL-тест моделирует падение после durable pause до завершения родительской транзакции; написан, но пропущен. Не объявлять подтверждённым на реальном сервере. |
| Предпросмотр/возобновление без сброса бюджета | PostgreSQL-тесты истории, идемпотентности, сохранения 15 попыток и явного повтора старой ошибки написаны, но пропущены. При повреждённом журнале unit-проверка требует проверки истории и не разрешает автоматическое возобновление. |
| /status и приватность | Текст различает паузу оплаты и суточный лимит; коды выводятся через allowlist. Реальная интеграция /status/публичной проекции с PostgreSQL написана, но пропущена. Существующие JS-проверки пройдены. |
| Реальная публикация и получение подписчиком | Не выполнено; нужны обновление и запуск пользователем после проверки средств. |

## Изменения и ограничения

- `worker/provider.py` — общие функции и явная CLI-команда; не отдельный сервис. Состояние хранится append-only в существующем runs, service=worker_provider_state, status=paused/resumed, note=версионированный JSON. Новых таблиц и миграции нет. Резюме ссылается на предыдущую запись; повторное резюме не добавляет строку.
- Worker держит прежний session advisory lock 4208. Возобновление берёт тот же ключ, затем provider lock 4211; запись паузы на отдельном соединении берёт 4211, поэтому не ждёт родительского material lock и переживает его откат. Проверку этого поведения с PostgreSQL ещё нужно выполнить.
- При 402 текущий материал остаётся error, использованные попытка/вызов учитываются. Следующие collected остаются нетронутыми. Пауза сохраняется независимо от UTC-дня и ключа. Автоматического опроса баланса или повторов модели нет.
- 6000 токенов — верхний предел, а не гарантия полного/качественного ответа. При повторном усечении причина видна; не публиковать обрывок. Увеличенный предел может повысить требуемый резерв средств и потенциальную стоимость одного draft до 2.5 раза по выходным токенам; фактическая стоимость не измерялась.
- Пользователь сообщил о смене ключа, но доступный баланс нового аккаунта не проверен. Смена ключа того же аккаунта не исправляет отрицательный баланс.
- Исторические error автоматически не перепоставляются; новая rules_version позволяет явный повтор выбранных ID через T12 requeue с сохранением прежнего решения. Дневной бюджет не очищается даже после смены ключа.
- Откат к T13 теряет понимание паузы: старый Worker с неустранённой платёжной проблемой не запускать. Данные и журнал не удалять.

Инструкция: [Coolify T14](../specs/T14-provider-recovery/COOLIFY.md). Коммит/push и развёртывание отдельно согласуются.

## Продукт и редакционный вкус

Научно-популярное медиа для **обычных владельцев собак**: помогать понимать поведение, эмоции, потребности и повседневную жизнь собаки. Небольшая качественная лента, в перспективе библиотека, AI-помощник с источниками и необязательные идеи наблюдения.

Темы продукта в перспективе: поведение/эмоции/когнитивные способности, обучение, благополучие, здоровье, питание, технологии, законодательство. **Текущий пилот: поведение, обучение и благополучие**, русский язык, Telegram + существующая Mini App, автопубликация низкорисковых материалов.

Пользователь хочет интересные понятные истории: как собаки воспринимают мир, общаются, играют, учатся и живут рядом с человеком. Прямой практический совет не обязателен. Профессиональные клинические разборы, диагностические методики, стадии болезней и статистика для ветеринаров — неподходящая лента. Ветеринарный журнал сам по себе не запрещён: он может публиковать подходящие исследования поведения.

Существенные выводы связывать с внешним проверяемым источником; отличать результат от интерпретации, указывать ограничения. Аннотация не равна полному тексту. Собственная AI-публикация не независимое доказательство. Лечение, лекарства, лечебные диеты, опасные упражнения и другие рискованные предписания автоматически не публиковать. Количество не обеспечивать выдуманными выводами.

## Почему нужна T16 и что в ней сделано

Первая полученная статья — про сердечные шумы, аускультацию, MMVD/DCM и стадии болезни (LISTEN, DOI `10.3389/fvets.2026.1944439`), ошибочно под меткой «Благополучие». Пользователь хотела познавательную историю для владельца. Найдена конкретная лазейка: `trained` во фразе `cardiology-trained veterinarians` считалось обучением собак.

T16, утверждённый вариант B:

- Collector и Worker используют общий контекстный фильтр: обучение специалистов/моделей не подменяет обучение собак.
- Первый полный draft-ответ содержит `{editorial_fit, article}`. Fit проверяет аудиторию, фокус, вопрос владельца и точный фрагмент аннотации. При skip article=null, review/следующие ступени не выполняются. Дополнительного модельного вызова нет.
- Review независимо проверяет строгие bool owner_relevant/plain_language. Неподходящая аудитория — окончательный отказ; сложный язык подходящей истории допускает упрощение. «Благополучие» не остаточная категория для клинических работ.
- Известный checkpoint T15 получает свежий fit с сохранением migration_history; неопределённый старый paid-call удерживается. Старое одобрение не переносится в новый контракт.
- Версии **dogs-pilot-v6 / dogs-v6**. Модель по умолчанию `anthropic/claude-haiku-5.5` через OpenRouter; фактическую MODEL проверять в окружении. Draft=6000, review=2400; **30 попыток / 30 вызовов / 3 публикации UTC**. Бюджет не сбрасывать. При одном оставшемся вызове новая ступень ждёт следующего окна.
- Mini App: кремовый #F3EFE6, бумажные карточки #FAF8F3, зелёный #315644, собачьи эмодзи 🐕/🐶, 🎾, 🦴, 🐾, читаемый текст и согласованные светлые панели Telegram. Служебный web не подвергался редизайну.

## Полезные команды для пользователя в Terminal worker на Coolify

Проверка версии без запросов к модели:

```sh
python -c "from worker.editorial import RULES_VERSION; from worker.main import PROMPT_VERSION; print(RULES_VERSION, PROMPT_VERSION)"
```

Пауза оплаты: `python -m worker.provider` — только просмотр; `python -m worker.provider --resume` — явное возобновление после проверки средств, может запустить платную обработку/рассылку работающего Worker. Суточные бюджеты сохраняются.

Повтор выбранных ошибок: `python -m worker.requeue --ids 405 413` — пример предпросмотра, подставить реальные согласованные ID; `--apply` явно пишет collected и может запустить обработку. Не применять массово, не обходить uncertain_stage. `/status` отправляется боту. UTC-сброс — 00:00 UTC / 03:00 Москвы.

Для тестов использовать отдельную изолированную БД по tests/README.md, никогда не рабочую DATABASE_URL. Не выводить .env, API-ключи и строки подключения.

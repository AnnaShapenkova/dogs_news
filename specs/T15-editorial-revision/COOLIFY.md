# T15 — получить первые публикации по ступенчатой схеме

Код должен попасть в main отдельным согласованным коммитом, затем пользователь обновляет приложение на Coolify. Перед обновлением сохранить резервную копию БД; том не пересоздавать. Агент не запускал платные вызовы/рассылку и не развёртывал приложение.

## Проверить код Worker

В Terminal контейнера worker:

```sh
python -c "from worker.editorial import RULES_VERSION; from worker.main import PROMPT_VERSION, OUTPUT_TOKENS; from worker.budget import MAX_ATTEMPTS; print(RULES_VERSION, PROMPT_VERSION, OUTPUT_TOKENS, MAX_ATTEMPTS)"
```

Ожидается `dogs-pilot-v5 dogs-v5 {'draft': 6000, 'review': 2400} 30`. Команда только читает код.

## Дать обработать уже собранное

В последней диагностике было 32 collected и 15/15 использованных попыток. В T15 предел 30: старые 15 сохраняются, после обновления остаётся до 15 дополнительных попыток, пока другие расходы не изменились. Новый сбор при существующей очереди не требуется. Работающий Worker может начать обработку сразу после обновления: это платные запросы и возможная автоматическая публикация/рассылка.

Проверить положительный баланс и лимит рабочего ключа в OpenRouter. В терминале:

```sh
python -m worker.provider
```

Если paused=true, после устранения оплаты явно возобновить:

```sh
python -m worker.provider --resume
```

Смена ключа сама паузу не снимает. При paused=false команда возобновления не нужна. Пауза оплаты и исчерпанный суточный бюджет — разные основания остановки.

## Как читать результат

Отправить боту `/status`. Старые накопительные удержания сохраняются. Отдельный блок «Последние решения текущей версии за сутки UTC» покажет результат именно T15 и формат/этап отказа. Это последние решения материалов, не полная история всех их старых попыток.

- Разбор: 120–220 слов, 2–4 абзаца.
- Короткое объяснение: 80–120 слов, 1–2 абзаца.
- Научная заметка: 40–80 слов, один подтверждённый результат.

На каждой ступени ограничения и источники обязательны. После трёх отказов материал удерживается, обрабатывается следующий. Цель — до 3 публикаций; фактическое число может быть 0 при недостаточности корпуса или ошибках.

Общий предел — 30 попыток / 30 модельных вызовов / 3 публикации UTC. На новую ступень требуется пара вызовов, поэтому при 29/30 может появиться ожидание новых суток. Пройденные ступени сохраняются; после нового окна продолжается оставшаяся. Время обновления видно в /status. Не удалять runs и не менять timestamps для снятия лимита.

## Старые удержания и сбои

Имеющиеся held/error сами не возвращаются. Для выбранных согласованных ID использовать прежний предпросмотр `python -m worker.requeue --ids ...`, затем явный `--apply` только если все eligible=true. Старую failed-очередь не менять. uncertain_stage означает, что результат прежнего оплаченного запроса неизвестен; не пытаться массовым повтором обойти его защиту.

При новом нулевом результате прислать полный /status с блоком текущей версии и итог Worker. При успехе — текст хотя бы одной публикации с ограничениями/источником, её формат и подтверждение получения сообщения. Успешный деплой или синтетический тест не подтверждает реальный выпуск.

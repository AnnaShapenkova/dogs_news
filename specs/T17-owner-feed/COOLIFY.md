# T17 — проверка и запуск пользователем на Coolify

Развёртывание агентом не выполнялось. Коммит/push T17 отдельно согласовать. Новых служб, моделей, таблиц и зависимостей нет. В существующей БД расширяется CHECK content_scope, добавляются новые sources; старые строки/том сохраняются. Нужны резервная копия и рабочий способ её восстановления. Производственную БД нельзя использовать как тестовую.

## Файл подготовки коммита и отправки

В корне подготовлен COMMIT-T17.bat, агентом не запускался. Его открытие пользователем создаёт отдельный коммит T17 и делает обычный push в origin/main. Сначала проверяются точный origin dogs_news, ветка main, пустой индекс и отсутствие опережающих изменений origin/main. Явный список файлов не включает evaluation/, .env, .tools, сам BAT или его лог. При расхождении/ошибке файл останавливается, без force push/автоматического merge/reset. safe.directory действует только для этой папки и только в командах файла. Результат — COMMIT-T17.log. Скрипт не запускает тесты, платную модель, requeue или развёртывание. До запуска пользователь отдельно согласует коммит/push; подготовленный BAT сам по себе не является отправкой.

## Порядок обновления

1. Остановить Worker и внешние задания Collector на время обновления. Сделать backup существующей БД; не пересоздавать том. Проверить, что bot и Worker используют ту же существующую БД.
2. После согласованного push обновить bot и web до T17: они читают payload v1/v2. Инициализация схемы расширяет CHECK и добавляет источники идемпотентно, пользовательские active сохраняются. Убедиться, что страницы открываются; старые статьи не удаляются.
3. До включения Worker выполнить один сбор из Terminal обновлённого bot-контейнера в /app: `python -m collector.main`. Это реальный сбор/запись в БД и внешние HTTP GET, но без модели и рассылки; оператор запускает его сам. Если сбор выполняется существующим отдельным заданием, использовать его вместо дублирующего запуска.
4. Посмотреть результат сбора: должны присутствовать строки RKF: Owner guides, Pets: Learning, Pets: Nutrition, PLOS: Dogs, старые два источника. Ошибки/403/429 не скрываются; недоступность одного не означает успех его сбора. Если всё новое недоступно, сначала разобраться с доступом, а не тратить модельный бюджет на старую клиническую очередь.
5. Обновить/включить Worker. Это может сразу начать платные запросы и автоматические публикации из collected. Бот может разослать допущенные карточки. В пределах текущих UTC-суток сохраняется уже потраченный бюджет; новые пределы 8 публикаций / 60 попыток / 80 вызовов, не новый бесплатный бюджет.
6. Настроить существующее задание Collector на 00:05, 06:05, 12:05, 18:05 UTC (03:05, 09:05, 15:05, 21:05 Москва). Не запускать параллельно дублирующие расписания. Worker сам Collector не вызывает. Перезагрузить Mini App после обновления её шаблона.

## Проверка версии без ключей

В Terminal Worker:

```sh
python -c "from worker.editorial import RULES_VERSION; from worker.main import PROMPT_VERSION; from worker.budget import MAX_PUBLICATIONS, MAX_ATTEMPTS, MAX_MODEL_CALLS; print(RULES_VERSION, PROMPT_VERSION, MAX_PUBLICATIONS, MAX_ATTEMPTS, MAX_MODEL_CALLS)"
```

Ожидается `dogs-pilot-v7 dogs-v7 8 60 80`. Если bot обновлён, а Worker нет, их версии могут расходиться; проверять нужный контейнер. Не выводить .env, ключи, DATABASE_URL и полный ответ провайдера.

Платёжная пауза не снимается обновлением: `python -m worker.provider` показывает состояние, не меняя его. Прежний `--resume` — только явное действие после проверки оплаты. В этой задаче агент не запускает его.

## Что проверяет пользователь

- Первый полный UTC-день с работающим расписанием: минимум пять содержательных карточек, разные темы (цель — минимум три), понятный язык владельцу, без профессиональной клиники.
- Карточка: заголовок, краткое содержание на русском, тип/тема, источник, «Читать оригинал». Приоритет русских оригиналов, иностранная ссылка отмечена. Нет обязательного блока ограничений. Дата давнего материала не маскируется свежей новостью.
- Питание видно в фильтре, чтение/возврат/навигация работают, ссылки ведут в ожидаемый источник, старые статьи доступны. Светлая тема T16 сохраняется. На телефоне проверить 320–430 px; Node-тест не проверяет фактическую вёрстку.
- /status различает очередь автообработки, отложенное по бюджету, удержания автоматикой и технические ошибки. Исторические причины отдельно от текущей версии/суток. Ноль удержанных не является целью: клинические/опасные/неподтверждённые материалы должны отсеиваться.
- Если меньше пяти: прислать полный /status, строки последнего сбора и причины текущей версии; отметить как недостигнутую цель. Не обнулять runs и не перепоставлять все held. Продолжать проверку доступности источников, пригодности пула и расхода бюджета.
- Прислать тексты новых карточек/ссылки и скриншот Mini App для редакционной и визуальной приёмки. Тесты с подменённой моделью не подтверждают качество живых текстов или достаточность ежедневного потока.

## Дополнительные ограничения проверки

Локальная PostgreSQL недоступна: SQL-миграция, конкурентные резервации и полный цикл с реальной БД пока не проверены. Для тестов предусмотрена только отдельная локальная project_dog_t01_test; в рабочей БД тестовый suite не запускать. Не объявлять приёмку завершённой по факту запуска страницы.

РКФ/«Питомцы» дают смешанное по качеству содержание. Официальный источник не даёт автоматический допуск всем советам. PLOS проверяется через API/JATS и лицензию; robots журнала требует Crawl-delay 30 секунд, поэтому проверка может занять время. При 403/429 сохраняется пауза источника с Retry-After; принудительно обходить её не нужно.

## Откат

Остановить Worker, выключить новые sources через согласованное операторское действие, сохранить новые материалы/audit/payload v2 и расширенный CHECK. Не сужать CHECK и не удалять новые строки ради старого кода. Оставить reader, умеющий v1/v2. Старый Worker не должен обрабатывать новые provider. Никаких массовых сбросов, force push или удаления тома.

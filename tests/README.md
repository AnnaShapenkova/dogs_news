# Проверка T01

Целевая среда: Python 3.12, PostgreSQL 17 и зависимости из корневого requirements.txt. Тесты используют стандартный unittest; дополнительный Python-фреймворк не нужен. Проверка клиентского пустого состояния использует установленный Node.js, без npm-пакетов.

## Запуск

Создайте отдельную **локальную тестовую** БД `project_dog_t01_test` на PostgreSQL 17. Не используйте будущую рабочую БД Coolify. Пользователю тестовой БД нужны права создавать и удалять схемы. Пример запуска из корня проекта в PowerShell:

```powershell
$env:PYTHONUTF8 = '1'
python -m pip install -r requirements.txt
$env:TEST_DATABASE_URL = 'postgresql://postgres@127.0.0.1:55439/project_dog_t01_test'
python -m unittest discover -s tests -p 'test_*.py' -v
node tests/test_mini_app.js
git diff --check
```

Адрес и пользователь в примере относятся к отдельному локальному кластеру; замените порт и параметры доступа на параметры своей тестовой БД. Код тестов не читает DATABASE_URL. Допускаются только loopback-адрес и точное имя БД `project_dog_t01_test`; для каждого теста создаётся случайная схема, которая удаляется после проверки. Существующие таблицы вне этой схемы не изменяются. Не подключайте к тестовому серверу исходные production-тома.

Без TEST_DATABASE_URL выполняются только два теста формирования сообщений; PostgreSQL-проверки будут явно пропущены. Такой запуск не подтверждает все критерии T01. Ошибка подключения к заданной тестовой БД считается ошибкой тестов, а не пропуском.

## Изоляция и покрытие

Telegram API и вызов модели заменены тестовыми ответами. Внешний HTTP в PostgreSQL-тестах запрещён. Проверки HTTP-интерфейсов запускают только обработчики на случайных loopback-портах, без main(), Telegram polling и сборщика. Данные — синтетические, со ссылками на домены .invalid.

Проверяются создание и повторная инициализация схемы, DEFAULT/NOT NULL/CHECK, сохранность записей, отсутствие импорта props, все читательские SQL-пути, счётчики, /start, /status, рассылка и setup, sent_at черновиков, ограничение LATEST, сохранение результата Worker как draft даже при поле published в ответе модели, HTTP-ответы и пустое состояние Mini App.

Проверка Node выполняет существующий inline JS с пустыми данными и минимальным DOM-макетом. Она проверяет рендеринг пустого состояния и скрытие фильтров, но не заменяет полноценную проверку в Telegram и браузере перед развёртыванием.

Локальные переносимые инструменты аудита/проверки находятся в `.tools/`, исключены из Git и Docker-контекста. Системные службы и ресурсы Coolify для T01 не создаются. После проверки локальный PostgreSQL необходимо остановить; файлы инструментов не удаляются автоматически.

## Запуск вне Windows sandbox на этом компьютере

Если используется подготовленная рабочая папка, переносимые Python 3.12.10 и PostgreSQL 17.6 уже находятся в `.tools/`. Ниже команды для обычного PowerShell **вне Codex sandbox**, из корня проекта. Используется новый каталог тестового кластера; если он уже существует, не повторяйте initdb и не удаляйте каталог автоматически. Порт 55439 должен быть свободен. Trust-аутентификация допустима здесь только для одноразового локального тестового кластера; это не настройка для Coolify или рабочей БД.

```powershell
$env:PYTHONUTF8 = '1'
$t01Root = (Get-Location).Path
$t01PgBin = Join-Path $t01Root '.tools\postgres17\pgsql\bin'
$t01Data = Join-Path $t01Root '.tools\pgdata-user-t01'
if (Test-Path -LiteralPath $t01Data) { throw 'Каталог уже существует: не переинициализируйте его автоматически.' }
& "$t01PgBin\initdb.exe" -D $t01Data -U postgres --auth-local=trust --auth-host=trust --encoding=UTF8 --locale=C
if ($LASTEXITCODE -ne 0) { throw 'initdb завершился с ошибкой' }
& "$t01PgBin\pg_ctl.exe" -D $t01Data -l "$t01Root\.tools\postgres-user-t01.log" -o '-h 127.0.0.1 -p 55439' -w start
if ($LASTEXITCODE -ne 0) { throw 'PostgreSQL не запустился' }
try {
    & "$t01PgBin\createdb.exe" -h 127.0.0.1 -p 55439 -U postgres project_dog_t01_test
    if ($LASTEXITCODE -ne 0) { throw 'Тестовая БД не создана' }
    $env:TEST_DATABASE_URL = 'postgresql://postgres@127.0.0.1:55439/project_dog_t01_test'
    & .\.tools\python312\tools\python.exe -m unittest discover -s tests -p 'test_*.py' -v
    if ($LASTEXITCODE -ne 0) { throw 'Python-тесты не прошли' }
    node tests/test_mini_app.js
    if ($LASTEXITCODE -ne 0) { throw 'JavaScript-проверка не прошла' }
} finally {
    & "$t01PgBin\pg_ctl.exe" -D $t01Data -m fast -w stop
    Remove-Item Env:TEST_DATABASE_URL -ErrorAction SilentlyContinue
}
```

Эти команды в обычной пользовательской оболочке ещё не проверены. Из sandbox initdb завершился ошибкой создания restricted token до запуска сервера; проверка в обычном PowerShell нужна для продолжения приёмки. Если есть другой локальный PostgreSQL 17, достаточно создать в нём отдельную БД и использовать общую инструкцию выше.

## Выбранное продолжение: проверка в Coolify

Пользователь решил отправить код до завершения PostgreSQL-тестов и выполнить их в Coolify. Локальную БД создавать не требуется. Скрипт `.tools/push-t01.ps1` предназначен только для коммита и push; `.tools/complete-t01.ps1` с локальной БД для этого сценария не используется. Оба файла локальные и не входят в Git.

Для полной проверки на сервере используйте отдельную тестовую PostgreSQL 17 и базу `project_dog_t01_test`. Тесты сохраняют защиту: адрес подключения только loopback. Поэтому обычный адрес Compose-сервиса `postgres` не подойдёт; тестовому Python-процессу нужен доступ к тестовой БД через loopback (например, общая с PostgreSQL сетевая среда контейнеров или защищённый туннель). Не подменяйте адрес рабочей БД и не снимайте проверку изоляции ради запуска.

В тестовом окружении нужны исходники T01 из master, Python 3.12 и requirements.txt. TEST_DATABASE_URL задаётся секретом окружения. Запуск: `python -m unittest discover -s tests -p 'test_*.py' -v`. Ожидаемый результат — все 15 тестов пройдены, без skipped. Telegram-токен и OpenRouter-ключ для этих тестов не нужны; реальные collector, worker и bot запускать не требуется. После результата обновите T01_RESULTS.md; до этого PostgreSQL-проверки считаются невыполненными.

Пользователь выбрал прямую отправку в master. Актуальный `.tools/push-t01.ps1` проверяет текущую ветку master и адрес origin, добавляет только согласованные файлы, создаёт коммит T01 и выполняет обычный push в origin/master. Он не создаёт ветку и не использует force.

Последующее уточнение: пользователь сменил назначение на AnnaShapenkova/dogs_news, ветка master. Для двойного щелчка подготовлен локальный PUSH-DOGS-NEWS.bat; результат сохраняется в PUSH-DOGS-NEWS.log. Старые локальные файлы отправки перенаправлены на новый файл. Батник меняет origin только с прежнего форка либо уже выбранного dogs_news, добавляет явный список файлов и не использует force. Автор коммита задаётся только для этой команды: GitHub-логин AnnaShapenkova и ID-based noreply, без изменения глобальных настроек Git.

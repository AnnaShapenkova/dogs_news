# Ближе к собаке — T02 и T03 для проверки на стенде

T02 собирает исследования через Europe PMC и популярные статьи из RSS ScienceDaily Dogs: до 15 новых кандидатов суммарно за проход, окно 90 календарных дней UTC. Сохраняются исходная запись, контекст и доступное содержание. Источники — [SOURCES.md](SOURCES.md), контракт сбора — [SPEC T02](specs/T02.md), публикации — [SPEC T03](SPEC.md).

T03 обрабатывает collected: сверяет научный источник, создаёт русский текст текущей моделью, проверяет подтверждающие фрагменты и отдельным запросом — риск/достоверность текста. Допущенные статьи становятся published и видны в Mini App/web/Telegram. Неподтверждённые, рискованные и недостаточные материалы остаются held/error с причиной. Старая AI-очередь new больше не обрабатывается автоматически.

**Состояние проверки:** 41 Python-тест пройден, 31 PostgreSQL-тест не выполнен; JS-проверки пройдены. По просьбе пользователя дальнейшие проверки остановлены, готовится фиксация в main для его проверки на стенде. Полная приёмка и реальная научная оценка публикаций не завершены. [Отчёт T03](tests/T03_RESULTS.md).

При запуске Worker с OPENROUTER_API_KEY включается реальная платная обработка: до 15 попыток и 30 модельных запросов за сутки UTC, до 3 публикаций. Без ключа входы остаются collected. Сбой источника/модели и отказ проверки не дают разрешения на публикацию; ноль публикаций допустим. /status показывает очередь, удержания и причины. Ограничения основаны на аннотации, а не на прочтении полного текста.

Перед обновлением уже запущенной T01 в Coolify: остановить внешние задания Collector, сделать backup PostgreSQL, затем применить код с транзакционным init_schema. БД и том не пересоздавать. Старые материалы/findings/подписчики сохраняются; пять старых AI-URL отключаются. Ручное отключение новых источников сохраняется при повторном запуске. Настройки Coolify агентом не проверялись; развёртывание и реальные задания пользователь выполняет отдельно.

## Проверить T02 и выполнить один сбор

Полный набор тестов: [tests/README.md](tests/README.md). Требуется отдельная тестовая БД; запуск страницы не заменяет интеграционные тесты. Локальный отчёт — [tests/T02_RESULTS.md](tests/T02_RESULTS.md).

После проверки и при разрешённом доступе к внешним источникам команда в контейнере с кодом и DATABASE_URL:

```text
python main.py collector
```

Это один проход. Предлагаемое расписание раз в сутки настраивается внешним заданием Coolify; Compose и Worker сами сбор не запускают. Для Collector не нужны OPENROUTER_API_KEY и TELEGRAM_TOKEN. Выборка может дать меньше 15 или ноль новых записей: это отражается в runs.note, с ошибками, пропусками и ограничением просмотра.

Проверки после сбора (только чтение, в PostgreSQL):

```sql
SELECT name, kind, active FROM sources ORDER BY id;
SELECT status, content_scope, count(*) FROM materials GROUP BY status, content_scope;
SELECT id, status, items, note FROM runs WHERE service='collector' ORDER BY id DESC LIMIT 5;
```

Ниже сохранена исходная документация транспорта. Примеры props не импортируются автоматически. Пользовательская ветка для нового обновления — main; рабочие данные/том не пересоздавать.

```
Europe PMC / ScienceDaily -> collector -> Postgres: collected
collected -> worker: источник, русский текст, проверки -> published / held / error
Postgres: published -> bot (Telegram и Mini App) / web
```

Пять блоков, каждый со своей работой:

| Блок | Что делает | Файл |
|---|---|---|
| collector | собирает материалы из источников, один проход и выход | `collector/main.py` |
| Postgres | хранит источники, материалы, находки, прогоны и подписчиков | `db/schema.sql` |
| worker | раз в 10 секунд берет новые материалы и отдает их модели | `worker/main.py` |
| bot | запоминает, кто нажал Start, после разбора присылает одну сводку, показывает ленту внутри Telegram | `bot/main.py`, `bot/template.html` |
| web | показывает схему блоков, счетчики и последние находки | `web/main.py` |

Код один на все блоки: `main.py` запускает тот блок, как называется сервис на Railway (`web`, `collector`, `worker`, `bot`). Локально блок передается аргументом: `python main.py web`.

## Поднять у себя на Railway

### Кнопкой

[![Deploy on Railway](https://railway.com/button.svg)](https://railway.com/deploy/bFTvXF)

Railway создаст проект: Postgres и три сервиса из этого репозитория, без бота. Бота добавьте руками, пункты 3, 4 и 5 ниже. Попросит один ключ, `OPENROUTER_API_KEY`, его берут на https://openrouter.ai/keys. Когда все сервисы позеленеют, откройте адрес сервиса web.

collector работает по расписанию раз в шесть часов (по UTC). Обычно первый проход идет сразу после деплоя, и находки появляются через несколько минут. Если страница пустая, откройте collector, вкладку Deployments, и в меню последнего деплоя нажмите Redeploy: collector пройдет источники один раз.

### Руками

1. Сделайте форк этого репозитория.
2. В Railway создайте проект, добавьте в него Postgres.
3. Добавьте четыре сервиса из своего форка, назовите их `web`, `collector`, `worker`, `bot`. Имена важны: по ним `main.py` выбирает блок.
4. Каждому сервису добавьте переменную `DATABASE_URL` со значением `${{Postgres.DATABASE_URL}}`. Сервису worker добавьте еще `OPENROUTER_API_KEY`, сервису bot `TELEGRAM_TOKEN`: токен бота от @BotFather (команда `/newbot`).
5. У web и bot в настройках включите публичный адрес (Networking, Generate Domain), порт `8080`. Адрес bot нужен ленте внутри Telegram, бот берет его сам.
6. У collector в настройках задайте расписание (Cron Schedule), например `0 */6 * * *`: раз в шесть часов. Без расписания он пройдет источники один раз при запуске.

Railway берет деньги за использование. Поставьте лимит расходов в Usage.

## Поднять на своем сервере (Coolify и другие)

В репозитории лежит `Dockerfile`: рецепт, по которому сервер упаковывает код. Образ один на все блоки, блок выбирается переменной `BLOCK` (`worker`, `bot`, `web`). В Coolify это Build Pack **Dockerfile** и переменная `BLOCK` у каждой карточки. Сбор запускается задачей по расписанию внутри worker: `python main.py collector`.

На Railway `Dockerfile` тоже подхватывается, переменная `BLOCK` там не нужна: блок по-прежнему выбирается по имени сервиса.

## T16: истории для владельцев и светлая Mini App

Текущий Worker проверяет не только источник и риск, но и аудиторию. Первый полный draft-ответ включает закрытый editorial_fit с вопросом для владельца и точным фрагментом источника. Клинический/профессиональный сюжет удерживается без перехода к более коротким ступеням. Рецензент независимо подтверждает owner_relevant и plain_language; сложный язык подходящей истории можно упростить, несовпадение аудитории — окончательный отказ. Это тот же модельный вызов, без нового сервиса. Обучение ветеринаров больше не считается обучением собак.

Mini App получила кремовый фон, бумажные карточки, зелёные акценты и тематические собачьи эмодзи; Telegram-панели согласованы со светлой темой. Заголовок истории — главный элемент карточки, ограничения и первоисточник доступны в статье. Уже опубликованные материалы не переписываются.

Версии `dogs-pilot-v6 dogs-v6`, лимиты 30 попыток / 30 вызовов / 3 публикации UTC. [Coolify T16](specs/T16-owner-editorial-fit/COOLIFY.md), [результаты](tests/T16_RESULTS.md), [визуальное направление](specs/T16-owner-editorial-fit/VISUAL.md). ## T15: три ступени публикации

Текущий Worker пробует: разбор 120–220 слов → короткое объяснение 80–120 → научную заметку 40–80. После устранимого редакционного отказа он заново работает с исходной аннотацией и готовит более простой текст. Каждый новый текст получает собственную рецензию; требования к доказательствам и безопасности не снижаются. После трёх отказов материал удерживается, затем выбирается следующий кандидат.

Лимиты: **30 попыток / 30 вызовов модели / 3 публикации за сутки UTC**. Использованные попытки не удаляются. На новую ступень нужны два свободных вызова; один оставшийся вызов сохраняется до нового окна. Прогресс продолжается с оставшейся ступени, а не с первого текста. Неопределённый результат оплаченного запроса после сбоя требует разбора и не повторяется автоматически. Пауза 402 и явное возобновление T14 сохраняются.

`/status` отдельно показывает последние решения текущей версии за сутки и формат/этап отказа. Формат виден читателю, служебные рецензии и история — нет. Версии: `dogs-pilot-v5 dogs-v5`. [Запуск на Coolify](specs/T15-editorial-revision/COOLIFY.md), [результаты проверок](tests/T15_RESULTS.md). Реальная публикация и доставка ещё требуют проверки на стенде.

## T14: длина ответа и пауза оплаты

Worker запрашивает до 6000 выходных токенов для черновика и до 2400 для проверки текста. Усечённые ответы не публикуются. Модель и редакционные проверки сохраняются.

После первого HTTP 402 обработка следующих кандидатов приостанавливается; пауза хранится в существующем журнале БД и видна в `/status`. Перезапуск, смена ключа и новые сутки её не снимают. Проверить состояние в терминале worker: `python -m worker.provider`. После проверки средств явно возобновить: `python -m worker.provider --resume`. Работающий Worker может сразу начать платную обработку и рассылку; суточные лимиты 3/15/30 сохраняются. Прошлый error не возвращается в очередь автоматически.

Версии: `dogs-pilot-v4 dogs-v4`. Инструкция: [Coolify T14](specs/T14-provider-recovery/COOLIFY.md); проверки: [T14_RESULTS.md](tests/T14_RESULTS.md). Новых сервисов, моделей, источников или SQL-миграций нет. Реальная публикация на стенде ещё не подтверждена агентом.

## T13: расширенный поиск и познавательные разборы

Поиск Europe PMC проходит до 10 страниц / 150 записей: до 7 страниц за последние 90 дней, оставшиеся страницы — исследования до 5 лет. Общий лимит 15 новых кандидатов сохраняется, из них максимум 5 давних; RSS остаётся в окне 90 дней. Дубли не расходуют лимит вставок. Достижение предела просмотра не означает полного обхода корпуса.

Тексты допускаются от 80 до 220 слов в 1–4 абзацах. Дата давнего исследования и пометка «Познавательный разбор» показываются в Mini App, web и Telegram. Безопасные отрицания не отклоняются по одному слову; требования к источнику, цитатам и безопасности сохраняются. Модель, лимиты 3/15/30, 2400 max_tokens не изменены; PLOS и Jev не подключены. Версии: `dogs-pilot-v3 dogs-v3`.

После согласованной отправки и обновления на Coolify нужен новый сбор: Worker сам не запускает Collector. Старые held/error сами не возвращаются на проверку. Порядок: [Coolify T13](specs/T13-content-supply/COOLIFY.md), [проверки T13](tests/T13_RESULTS.md). Реальный выпуск на стенде пока не подтверждён.

## T12: первые публикации и повторная обработка

В T12 чувствительные слова в исследовании служат сигналом для проверки содержания, а не автоматическим запретом. Практические предписания запрещены, источник и цитаты проверяются, готовый текст проверяется отдельным запросом к текущей модели. Jev не подключён. Модель и лимиты 3 публикации / 15 попыток / 30 вызовов UTC сохранены.

`/status` показывает точные причины ошибок модели и состояние суточного бюджета. held/error автоматически не сбрасываются. Явная команда `python -m worker.requeue --ids 101 102` даёт предпросмотр; `--apply` возвращает пригодные выбранные материалы в collected с сохранением истории, после чего работающий Worker может начать платную обработку и рассылку. Команда не сбрасывает бюджет.

Подробности: [инструкция для Coolify](specs/T12-editorial-policy/COOLIFY.md), [SPEC](SPEC.md), [результаты проверок](tests/T12_RESULTS.md). Реальный выпуск ещё требует проверки пользователем на стенде; локальные тесты не подтверждают доставку.

## Поднять на своем компьютере

Нужны Python 3.12 и Postgres.

```
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env        # впишите свои значения
set -a; source .env; set +a
python main.py collector    # собрать материалы, проходит один раз и выходит
```

worker, web и bot работают, пока их не остановить (Ctrl+C), поэтому каждый запускается в своем окне терминала. В каждом новом окне сначала `source .venv/bin/activate` и `set -a; source .env; set +a`.

```
python main.py worker       # окно 2: разбирает материалы моделью
python main.py web          # окно 3: страница на http://localhost:8000
python main.py bot          # окно 4: бот и лента на http://localhost:8080
```

Лента внутри Telegram открывается только по адресу с `https`. Локально для этого нужен туннель, например `cloudflared tunnel --url http://localhost:8080`, а его адрес записывается в переменную `MINI_APP_URL`.

Таблицы создаются сами при первом запуске любого блока.

## Что поменять под свой рынок

- Источники пилота: два seed в конце `db/schema.sql`; Collector обходит только согласованные имена. Старые пять AI-URL остаются отключёнными.
- Общий лимит `MAX_NEW`, окно `LOOKBACK_DAYS` и распределение `QUOTAS` находятся в `collector/main.py`. Лимит вставок проверяется после дублей, общий для обоих источников.
- Редакционные запросы: `DRAFT_PROMPT` и `REVIEW_PROMPT` в `worker/main.py`; проверяемые правила и источники — `worker/editorial.py`. Самооценка модели не заменяет программные проверки.
- Модель: переменная `MODEL`, по умолчанию `anthropic/claude-haiku-5.5` через OpenRouter.
- Сколько свежих находок в сводке бота: `LATEST` в `bot/main.py`, остальные лежат в ленте.

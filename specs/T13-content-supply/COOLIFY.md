# T13 — проверка публикаций на Coolify

Сначала согласованный коммит/push в main и обновление пользователем. Перед обновлением сохранить резервную копию БД; том не пересоздавать. Новых SQL-миграций и источников в T13 нет. Агент не выполнял развёртывание и не запускал рабочую обработку.

## Проверить версии

В Terminal контейнера worker:

```sh
python -c "from worker.editorial import RULES_VERSION; from worker.main import PROMPT_VERSION; print(RULES_VERSION, PROMPT_VERSION)"
```

Ожидается `dogs-pilot-v3 dogs-v3`. Эта команда не обращается к модели и БД.

## Получить новые кандидаты

Worker не запускает Collector. Если сбор назначен в Coolify по расписанию, дождаться нового запуска с обновлённым образом. Для явного сбора вместо ожидания пользователь может в терминале контейнера приложения с кодом T13 и DATABASE_URL выполнить:

```sh
python main.py collector
```

Это реальный сбор с записью collected в рабочую БД. Работающий Worker может сразу потратить модельный бюджет, опубликовать и разослать допущенные материалы. Запускать только в согласованном рабочем окружении. Отдельно убедиться, что плановый Collector также обновлён: изменился не только Worker.

В отчёте должны появиться число страниц (до 10), архивные записи и число давних новых кандидатов (не больше 5). Сбор 0 не считать ошибкой автоматически: посмотреть дубли, предел просмотра и причины. Новые кандидаты не гарантируют опубликованный результат.

## Проверить выпуск

Отправить боту `/status`. При свободном бюджете новые collected обрабатываются автоматически. Сохраняются 3 публикации, 15 попыток, 30 вызовов за сутки UTC; при исчерпании ждать ближайшего обновления окна, журнал не очищать.

Давнее исследование показывается как «Познавательный разбор · исследование от ГГГГ-ММ-ДД». В публикации нужны проверяемый источник, ограничения и разделение результата/интерпретации. Прислать текст публикации и подтверждение получения сводки; если публикаций 0 — полный /status и последние итоги collector/worker без ключей.

Старые held/error сами не возвращаются. Для выбранных ID после предпросмотра остаётся команда из [T12](../T12-editorial-policy/COOLIFY.md); она сохраняет историю и не обходит бюджет. Не перепоставлять всю очередь и не переводить findings в published вручную.

## Откат

Остановить Worker, сохранить БД и аудит, вернуть код T12. Архивные collected не удалять; уже опубликованные записи автоматически не скрывать. Старый код может снова удержать архивные материалы. Производственную БД не использовать для тестов: PostgreSQL-проверкам нужна отдельная изолированная БД по tests/README.md.

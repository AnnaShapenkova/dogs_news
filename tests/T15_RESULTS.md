# T15 — результаты проверки и ограничения

Реализована утверждённая ступенчатая версия SPEC T15. Реальная публикация/доставка на Coolify не проверена: агент не вызывал платную модель, не менял рабочую БД и не развёртывал приложение. При 0 публикаций операционная цель не достигнута.

## Запуски

Python 3.12.10: `python -m unittest discover -s tests -p 'test_*.py' -q` — 140 тестов, 89 пройдены, 51 PostgreSQL-тест пропущен (TEST_DATABASE_URL отсутствует). `node tests/test_mini_app.js` — оба сценария пройдены. Проверены пустая лента и статья/заметка, ограничения, источники, экранирование и скрытие служебных полей.

test_t15.py использует синтетические источники, ответы и FakeBudget. Он проверяет контроллер, но не атомарность SQL, а подменённая рецензия не доказывает научную истинность. Отдельные PostgreSQL-тесты написаны, но в этой среде не выполнены.

## Критерии приёмки

| Критерий SPEC | Результат |
| --- | --- |
| 1. 30 попыток и прежние 30 вызовов/3 публикации | Общий отчёт и блокировка последнего одиночного вызова проверены локально. PostgreSQL-тест 15 старых попыток → новая обработка → блокировка при 30 написан, но пропущен; прежние SQL-тесты лимитов обновлены. |
| 2. Проход ступеней 1/2/3 | Локально проходят 2 вызова для первой, 3 для второго после неверной цитаты, 6 для третьей после двух отказов review. Сохраняется история, следующий формат получает исходник и безопасные коды, не текст отвергнутого вывода. SQL-путь до заметки и Telegram написан, но пропущен. |
| 3. Конечный отказ и учёт | После трёх отказов четвёртой ступени нет; неизвестный результат запроса не повторяется. Контроллер проверен локально, SQL-сценарий следующего кандидата/резерваций написан, но пропущен. |
| 4. Безопасность | Локально проверены опасный draft → новый безопасный формат, запрет допуска всех опасных вариантов, неизвестный риск/insufficient source, инъекции в скрытом claim и reviewer reasons, неверный review-контракт. Это механизм; оценка модели на реальных исследованиях остаётся неизвестной. |
| 5. Ошибки/продолжение | Локально проверены остановка при 402/таймауте/невалидном JSON, переход к более короткому формату при length, отсутствие новой ступени при одном вызове, продолжение со ступени 2, восстановление известного draft только рецензией, остановка при неопределённом платном запросе. SQL-тесты отката/нового соединения/смены исходника написаны, но пропущены. |
| 6. Читательский формат | Проверены тексты 40–80 слов с одним claim, метки формата в allowlist проекции, web и Telegram-строках, JS Mini App. Приватная история не публикуется. Содержательность результата проверяет review; автоматические тесты не доказывают её для живой модели. |
| 7. Изолированные проверки | 89 Python + JS пройдены; 51 PostgreSQL явно пропущен. |
| 8. Настоящий выпуск | Не выполнено: требуется обновление, доступный баланс и согласованная работа на Coolify. |

## Данные, восстановление и остаточные риски

- worker/stages.py — функции внутри существующего Worker, не отдельный сервис. Существующие таблицы/источники/модель сохранены; SQL-миграции нет.
- materials.editorial_result хранит версию, hash, историю трёх форматов и следующую ступень. Для переживания отката родительской транзакции Budget.checkpoint сохраняет тот же аудит в runs.worker_attempt на отдельном autocommit connection. Резервации worker_model_call имеют структурированный version=2 note с material_id, rules, phase, format_stage; finish сохраняет эти поля. Старые строки считаются историческими.
- На продолжении сверяются hash, модель/промпт и источник. Известный сохранённый draft получает собственную рецензию; незавершённая фаза с уже существующей резервацией не отправляется повторно. При uncertain_stage материал требует разбора, его не следует массово перепоставлять или очищать историю.
- Прогресс может иметь достаточно полный подтверждённый review при откате самой вставки публикации. Тогда повторная попытка перепроверяет сохранённый текст и актуальный источник, не создавая новый оплаченный draft/review для того же текста.
- Ступени требуют до 6 вызовов на кандидат; потолок 30 вызовов может остановить цикл раньше 30 попыток. Один оставшийся вызов не начинает новую ступень; в этом случае /status объясняет ожидание пары вызовов.
- 6000/2400 токенов и платёжная пауза T14 сохранены. Новый ключ сам по себе не доказывает доступный баланс; при 402 первый отказ приостанавливает цикл.
- Старые held/error не перепоставляются сами, legacy failed не обрабатывается. Финальный отказ новой версии нельзя перепоставить той же версией в обход истории.
- Сохранение checkpoint/резерваций, advisory locks и публичные SQL-запросы требуют реальной PostgreSQL-проверки. Не объявлять эту часть подтверждённой по FakeBudget.

Операционная инструкция: [Coolify T15](../specs/T15-editorial-revision/COOLIFY.md). Коммит/push, платные вызовы и развёртывание отдельно согласуются.

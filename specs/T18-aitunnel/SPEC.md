# T18 — AITunnel: GLM пишет, Haiku проверяет

Статус: УТВЕРЖДЕНО пользователем сообщением «утверждаю». Пользователь согласовал полную замену OpenRouter и роли моделей. Утверждённая версия генератора — GLM 4.7. Утверждённая T17 сохранена в specs/T17-owner-feed/SPEC.md; её живая/PostgreSQL/визуальная приёмка остаётся незавершённой.

## Результат и выбранный вариант

Один AITUNNEL_API_KEY, только https://api.aitunnel.ru/v1/chat/completions, Authorization: Bearer. OpenRouter полностью удаляется из действующего подключения, без запасного маршрута.

- DRAFT_MODEL=glm-4.7: первый editorial_fit, пересказ и доработка.
- REVIEW_MODEL=claude-haiku-5.5: проверка аудитории, доказательств, понятности и безопасности.

GLM 4.7 предлагается как фиксированный начальный вариант, присутствующий в каталоге AITunnel. Качество пересказа этой моделью пока не проверено. Это не утверждение о её превосходстве. ID моделей независимо настраиваются в Coolify.

Вариант A, выбранный пользователем: fit вместе с первым draft GLM, затем Haiku review — два вызова на обычную ступень. Вариант B, отдельный предварительный отбор Haiku, добавляет вызов и не входит в задачу. Haiku независимо проверяет owner_relevant: самооценка GLM не разрешает публикацию.

## Фактическое состояние

worker/main.py жёстко использует URL OpenRouter, OPENROUTER_API_KEY и единую MODEL (anthropic/claude-haiku-5.5) для обоих этапов. Ключ проверяется также в main/process_new. Compose передаёт старый ключ и MODEL. Audit/checkpoint и findings.model предполагают одну модель; восстановление сравнивает прежнюю model с текущей. Поэтому одной замены ключа/URL недостаточно.

Первый ответ содержит fit+article; stages.py выполняет до трёх ступеней и шести вызовов. Пауза 402 сохраняется в runs до явного --resume; тексты статуса и диагностические коды привязаны к OpenRouter.

## Границы

Сохраняются источники, темы, светлая Mini App, контракты T17, проверки безопасности, длины текстов, сбор и рассылка. Увеличение подробности и редакционная настройка по примерам — следующие отдельные требования; смена сервиса сама по себе не решает ветеринарный уклон.

Сохраняются temperature=0.2, draft max_tokens=6000, review=2400, response_format=json_object, нестриминговый ответ, timeout=60 секунд и прежняя политика повторов. Если API отвергает параметры, явно фиксировать ошибку, без скрытой смены модели или ослабления контракта. Реальная совместимость ключа/параметров требует отдельной живой приёмки.

Старые OPENROUTER_API_KEY и MODEL не служат fallback. Отсутствие AITUNNEL_API_KEY не включает обработку даже при наличии старого ключа. Пустые явно заданные имена моделей — ошибка конфигурации до резервирования вызова. Никаких новых зависимостей/служб/таблиц.

## Бюджет, аудит и ошибки

Единый бюджет 8 публикаций / 60 попыток / 80 вызовов UTC. Два этапа учитываются в общем счётчике; смена сервиса/моделей не сбрасывает бюджет. На новую ступень нужны два свободных вызова. Максимум шесть вызовов за три ступени.

В закрытых runs и editorial_result сохранять provider=aitunnel, phase и фактическую модель каждого нового вызова, конфигурацию двух моделей и происхождение восстановленных ответов. findings.model для новых публикаций — генератор; модель review хранится в закрытом аудите. Старые значения не переписывать. Предлагаемые версии dogs-pilot-v8 / dogs-v8 различают процесс, без расширения редакционной политики.

HTTP 402 сохраняет паузу и останавливает следующие попытки. Новые диагностические коды — только явный allowlist из документации; неизвестное тело даёт безопасный http_status. Не сохранять ключи, Authorization, сырой error body или произвольные сообщения сервиса. Исторические события OpenRouter читать как прежде и не выдавать за новую ошибку AITunnel.

Смена сервиса/ключа/UTC-дня не снимает старую паузу. --resume остаётся явным действием оператора с историей. 400/401/403/429/5xx, обрыв, таймаут, плохой/обрезанный JSON не разрешают публикацию, не вызывают запрос к другой модели/провайдеру или повтор неизвестного оплаченного результата.

## Данные, переход и откат

SQL-миграция не нужна: меняется версия JSON-аудита/checkpoint в существующих полях. Сохранить материалы, публикации, ID, статусы, историю и счётчики. Повторный запуск не создаёт новый бюджет.

- Неизвестный оплаченный generating/reviewing или резервация без проверяемого ответа — uncertain_stage, без автоматического повтора, включая старые v5/v6/v7.
- Известный сохранённый draft/ответ при неизменном исходнике и совместимом контракте повторно проверить программно, сохранить прежнее происхождение/migration_history. Проверенный fit можно сохранить; текст получает свежий review Haiku через AITunnel без повторной генерации. Старое одобрение не является новым допуском.
- Несовместимый/неполный checkpoint удержать с конкретной причиной без автоматической перегенерации. Повторная миграция уже обработанного checkpoint не повторяет review.
- При изменении DRAFT_MODEL/REVIEW_MODEL внутри T18 не переносить старое одобрение на другую конфигурацию. Хранить происхождение по этапам; неоднозначность удерживать без повторного платного вызова.
- Не перепоставлять published/held/error/failed массово. Requeue остаётся только по выбранным ID, preview по умолчанию; его допустимые источники/причины не расширяются. Старые опубликованные тексты не править.

Откат: остановить Worker, сохранить новые события/источники/публикации. Старый Worker не запускать поверх новых незавершённых checkpoint без проверки совместимости. Не удалять журнал/данные и не сбрасывать бюджет/паузу. Автоматического возврата к старому платному сервису нет.

## Критерии приёмки

1. Без нового ключа, включая наличие только старого, нет HTTP-вызовов/резервирования платных вызовов, очередь сохраняется. Ошибки конфигурации моделей выявляются до платной попытки.
2. Mock-транспорт подтверждает URL/авторизацию AITunnel, GLM для всех draft/исправлений, Haiku для всех review, отсутствие OpenRouter/fallback и скрытого MODEL override.
3. Первый GLM-ответ соблюдает fit+article; отрицательный Haiku review блокирует допуск. Неверный JSON/типы/пустой или обрезанный ответ не публикуются.
4. Сохраняются общий бюджет 8/60/80, конечность ступеней и правила начала/возобновления; запросы обеих моделей учтены вместе.
5. 402 останавливает следующие попытки, диагностика безопасна, прежняя пауза читается и не снимается переключением. Произвольные секреты из ошибок не попадают в аудит/статус.
6. Известный v7 draft получает новый review без повторного draft; неизвестный платный результат не повторяется. Проверены повторная миграция, смена конфигурации и сохранение истории; старые публикации доступны.
7. Аудит/события показывают модель и провайдера по этапам; findings.model — генератор. Читательские ответы не раскрывают закрытый аудит.
8. Подходящие изолированные Python/JS-проверки пройдены. PostgreSQL-сценарии запускаются только с отдельной тестовой БД; все пропуски/ограничения указаны в отчёте. Mock не доказывает качество моделей или реальную атомарность БД.
9. Инструкция Coolify описывает остановку Worker, замену env на AITUNNEL_API_KEY/DRAFT_MODEL/REVIEW_MODEL, проверку версии/конфигурации без ключей, сохранение паузы/данных и явное включение пользователем. Рабочие ключи/расходы/живое качество не объявлены проверенными по mock-тестам.

## Риски и разрешения

Возможны другие задержки, обрезание, качество русского и цена вызова. Лимит количества вызовов не гарантирует прежние денежные расходы. Доступность моделей конкретному ключу неизвестна до живой проверки.

Утверждение разрешает реализацию и изолированные тесты. Коммит/push, рабочая БД, платные вызовы, рассылка, resume и развёртывание агентом не разрешаются этой SPEC.
